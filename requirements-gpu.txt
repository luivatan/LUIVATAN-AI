# Apex AI — optional llama-cpp-python GPU installation guidance
#
# This file intentionally contains instructions instead of a portable pip
# requirement: the correct wheel index/build flag depends on the host GPU,
# driver, CUDA/toolkit version, operating system, architecture, and Python.
# The normal requirements.txt installation is CPU-capable by default.
#
# Choose ONE upstream-supported installation route and verify it for the host.
# If replacing the CPU build, --force-reinstall and --no-cache-dir prevent pip
# from silently reusing that cached wheel.
#
# NVIDIA CUDA prebuilt wheel (replace <cuda-version>, for example cu121, with
# a version actually supported by both the host and the upstream wheel index):
#
#   pip install --force-reinstall --no-cache-dir \
#     'llama-cpp-python>=0.3,<0.4' \
#     --extra-index-url \
#     https://abetlen.github.io/llama-cpp-python/whl/<cuda-version>
#
# NVIDIA CUDA source build (requires a compiler, CMake, and matching toolkit):
#
#   CMAKE_ARGS="-DGGML_CUDA=on" \
#     pip install --force-reinstall --no-cache-dir 'llama-cpp-python>=0.3,<0.4'
#
# Other upstream backends, including Metal, ROCm/HIP, Vulkan, and SYCL, use
# different indexes or CMake flags. Follow the current upstream instructions
# rather than copying a CUDA command to incompatible hardware.
#
# After installing an accelerated build, opt into layer offload in .env:
#
#   APEX_N_GPU_LAYERS=-1   # all layers, or use a measured smaller number
#
# Sentence-Transformers uses an available torch accelerator automatically.
# Select a host-compatible torch build with the official platform selector:
# https://pytorch.org/get-started/locally/
#
# Verify the installed backends on the target host before enabling offload;
# successful package installation alone does not prove GPU execution.
# No GPU is required; CPU-only operation remains supported.
